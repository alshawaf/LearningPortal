# البوابة التعليمية

نسخة أولية كاملة لمنصة عربية لتعليم البرمجة والتقييم الآلي. الواجهة React، والخلفية Fastify/TypeScript، وقاعدة البيانات PostgreSQL. صُممت طبقة الهوية بحيث لا تثق الواجهة بأي دور أو معرّف مستخدم ترسله؛ مصدر الهوية والصلاحيات دائمًا هو الجلسة المحفوظة في الخادم.

## البنية

```text
React (RTL) ── HTTPS + HttpOnly cookie ── Fastify API ── least-privilege role ── PostgreSQL
                                              │                                  │
                                      authorization hooks                 RLS + constraints
                                              │
                                      internal authenticated HTTP
                                              │
                                      isolated Runner service
                                              │
                                    ephemeral Python container
```

- `src/`: الواجهة، وسياق المصادقة، وعميل API.
- `server/src/routes/`: حدود HTTP والتحقق من المدخلات.
- `server/src/services/`: منطق حالات الاستخدام والمصادقة.
- `server/src/runner/`: خدمة تنفيذ مستقلة لا تمنح API وصولًا إلى Docker.
- `server/src/repositories/`: الوصول إلى البيانات فقط.
- `server/db/migrations/`: المخطط والسياسات والفهارس.
- `server/src/scripts/`: الترحيل، إنشاء المدير الأول، واختبار التكامل.

## تشغيل محلي

المتطلبات: Node.js 22+، pnpm، وDocker Desktop (أو Docker Engine على Linux). تستخدم PostgreSQL حاوية دائمة، بينما يستخدم كل تشغيل لتدريب Python حاوية مؤقتة منفصلة.

1. انسخ `.env.example` إلى `.env`، واستبدل **كل** قيم `replace-with-...` بأسرار مختلفة وعشوائية. لا ترفع `.env` إلى Git.
2. شغّل قاعدة البيانات ثم الترحيل وإنشاء المدير:

```bash
docker compose up -d postgres
docker pull python:3.12-alpine
pnpm install
pnpm db:migrate
pnpm db:seed
```

3. احذف قيم `BOOTSTRAP_ADMIN_*` من `.env` بعد نجاح `db:seed`، ثم شغّل النظام:

```bash
pnpm dev
```

الواجهة: `http://127.0.0.1:5173` — API: `http://127.0.0.1:4000/api/v1`.

أثناء التطوير تمر طلبات الواجهة عبر `/api` باستخدام وكيل Vite، بينما يبقى خادم API مستقلًا على المنفذ 4000. في الإنتاج يُضبط المسار نفسه في الوكيل العكسي أمام الواجهة والخادم.

تستخدم الواجهة روابط نظيفة مثل `/courses` و`/practices`. لذلك يجب أن يعيد خادم الإنتاج `index.html` عند طلب أي مسار واجهة غير موجود كملف فعلي. يتضمن المشروع إعداد Nginx جاهزًا في `deploy/nginx.conf`، ويحوّل `/api` إلى خدمة API باسم `api` على المنفذ `4000`. عدّل اسم المضيف فقط إذا كان اسم خدمة الخادم مختلفًا في بيئة النشر.

> يرفض الخادم البدء في بيئة الإنتاج من دون اتصال PostgreSQL مشفّر. شغّل الإنتاج خلف HTTPS، واستخدم أسرارًا من مدير أسرار، ولا تعرض PostgreSQL للشبكة العامة.

## الحماية المطبقة

- كلمات المرور محفوظة بـ Argon2id (ذاكرة 64 MiB، ثلاث دورات) ولا تُسجّل أو تُعاد عبر API.
- جلسات عشوائية معتمة؛ لا يُحفظ رمز الجلسة نفسه في القاعدة بل SHA-256 له فقط.
- Cookie للجلسة `HttpOnly` و`SameSite=Strict`، و`Secure` في الإنتاج.
- CSRF مزدوج الرمز لكل العمليات المعدِّلة، مع فحص صارم لـ `Origin`.
- قفل مؤقت بعد محاولات دخول فاشلة، وتحديد معدل الطلبات.
- إبطال كل جلسات المستخدم بعد تغيير كلمة المرور، وكلمة المرور المؤقتة تجبر المستخدم على استبدالها.
- RBAC لأدوار `admin` و`instructor` و`student` في الخادم، مع عزل إضافي بسياسات PostgreSQL RLS.
- حساب API محدود الصلاحيات ومنفصل عن حساب مالك المخطط/الترحيلات.
- سجل تدقيق لأحداث الدخول، الخروج، تغيير كلمة المرور، وإنشاء المستخدمين.
- تحقق Zod صارم، مهلات للاستعلامات، حد لحجم الطلب، وتعمية حقول الأسرار في السجلات.
- دخول موحّد بالبريد الإلكتروني أو رقم الجوال لكل الأدوار، مع تخزين الجوال بصيغة E.164 وفهرس فريد على مستوى قاعدة البيانات.
- تشغيل Python 3.12 في حاوية مؤقتة غير مميّزة الصلاحيات، بلا شبكة وبنظام ملفات للقراءة فقط، مع حدود للذاكرة والمعالج والعمليات والوقت.
- حالات الاختبار المخفية لا تعاد إلى واجهة الطالب، والحل المرجعي لا يظهر إلا للمدير أو أستاذ المقرر.
- نقاط التدريب تُمنح مرة واحدة فقط عند أول حل كامل، مع سجل محاولات وسجل نقاط منفصلين عن الواجبات والدرجات.

## التحقق

```bash
pnpm build
pnpm test
pnpm test:practice
pnpm test:architecture
pnpm test:integration
```

يتطلب `test:integration` قاعدة بيانات مهاجرة فقط؛ ينشئ الاختبار مديرًا وطالبًا مؤقتين ثم يحذفهما تلقائيًا. وينفذ دورة حقيقية تشمل الدخول، الجلسة، CSRF، إنشاء طالب، فرض تغيير كلمة المرور، رفض وصول الطالب لمسارات المدير، ثم إبطال الجلسة عند الخروج.

## نطاق النسخة الحالية

المصادقة والجلسات والمستخدمون والمقررات والتدريبات البرمجية والواجبات والتسليمات والدرجات ولوحات الإحصاءات مرتبطة بطبقة خلفية حقيقية. يفصل النموذج دليل المقررات الدائم عن التشغيل الأكاديمي: عام أكاديمي يحتوي فصولًا دراسية، ودفعة تخصصية تظهر في شعبة عند مستوى وعام محددين، والطالب ينتسب إلى الشعبة، ثم ينشئ المدير طرحًا يدويًا يربط المقرر بالشعبة والفصل والأستاذ. ترث الأنشطة والنتائج والطلاب سياقهم من هذا الطرح دون خطة دراسية أو تسجيل موازٍ قديم. تتيح واجهة الإدارة إدارة جميع هذه الكيانات، وتظهر واجهات الأستاذ والطالب فقط ما تسمح به العضوية وسياسات RLS. عند غياب السجلات تعرض الواجهة حالات فارغة وأصفارًا حقيقية بدل بيانات تجريبية. تشمل مرحلة التدريبات الحالية Python فقط، وتدعم نمطي `stdin/stdout` واستدعاء الدالة، والاختبارات العامة والمخفية، والمحاولات غير المحدودة، والنقاط التحفيزية. الواجبات الإلزامية والتقييم الزمني تبقى نطاقًا مستقلاً لمرحلة لاحقة.
