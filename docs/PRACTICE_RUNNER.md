# تشغيل التدريبات البرمجية

تستخدم مرحلة التدريبات Python 3.12 فقط. لا يمتلك خادم API صلاحية تشغيل Docker؛ فهو يرسل عقد تنفيذ داخليًا إلى خدمة Runner مستقلة، والخدمة وحدها تبدأ حاوية قصيرة العمر لكل طلب ثم تحذفها تلقائيًا.

## متطلبات التشغيل

- Docker Engine على Linux أو Docker Desktop في التطوير.
- صورة `python:3.12-alpine`، أو صورة داخلية مكافئة يحدد اسمها في `PRACTICE_RUNNER_IMAGE`.
- تشغيل خدمة Runner على مضيف تنفيذ مخصص يملك Docker CLI، مع إبقاء Docker socket بعيدًا عن API والواجهة.
- ضبط `PRACTICE_RUNNER_URL` و`PRACTICE_RUNNER_SHARED_SECRET` بين API وRunner. السر إلزامي ومستقل في الإنتاج.
- تقييد منفذ Runner على الشبكة الداخلية فقط؛ لا ينبغي نشر نقطة التنفيذ على الإنترنت حتى مع وجود السر الداخلي.

```bash
docker pull python:3.12-alpine
pnpm db:migrate
pnpm dev:runner
```

يفرض Runner حدًا للتنفيذات المتزامنة عبر `RUNNER_MAX_CONCURRENCY` وحدًا لطابور الانتظار عبر `RUNNER_MAX_QUEUE`. نقطة `/health` عامة لفحوص الجاهزية، بينما تتطلب نقطة التنفيذ سر Bearer داخليًا بمقارنة ثابتة الزمن.

## حدود العزل الحالية

- الشبكة معطلة (`--network none`).
- نظام ملفات الحاوية للقراءة فقط، و`/tmp` مؤقت صغير مع `noexec` و`nosuid`.
- التشغيل كمستخدم غير root، مع إسقاط جميع Linux capabilities وتفعيل `no-new-privileges`.
- حد ذاكرة 256 MiB، ونصف نواة CPU، و64 عملية، ومهلة عامة يحددها `PRACTICE_RUNNER_TIMEOUT_MS`.
- لكل حالة اختبار مهلة مستقلة بين 100 مللي ثانية و10 ثوانٍ.
- لا تُمرر متغيرات بيئة الخادم أو أسراره إلى الحاوية.

في الإنتاج واسع النطاق يوضع Runner في عُقد عمالية خاصة وتُثبت صورة Python بالـdigest بعد فحصها، مع مراقبة زمن الانتظار واستهلاك الموارد. التصميم الحالي يعزل التنفيذ عن API ويضع طابورًا محدودًا داخل كل Runner؛ وعند التوسع الأفقي يمكن استبدال البوابة الداخلية بطابور دائم دون تغيير مسارات التدريب العامة.

يعرض API نقطة `/ready` التي تتحقق من PostgreSQL ومن جاهزية Runner معًا، بينما تعرض خدمة Runner نقطة `/health` للاستخدام من موازن الحمل أو نظام المراقبة. لا تُعد نسخة API جاهزة لاستقبال المرور إذا تعذّر الوصول إلى Runner.

## الخصوصية ومنح النقاط

- التشغيل التجريبي ينفذ الحالات العامة فقط ولا ينشئ محاولة رسمية.
- التسليم الرسمي ينفذ جميع الحالات ويحفظ النتيجة، لكن واجهة الطالب لا تستقبل مدخلات أو مخرجات الحالات المخفية.
- الحل المرجعي يستخدم للتحقق قبل النشر ولا يعاد إلى حساب الطالب.
- سجل الإتمام له قيد فريد لكل طالب وتدريب؛ لذلك لا تمنح النقاط إلا لأول نجاح كامل حتى مع تكرار التسليم أو تزامنه.
